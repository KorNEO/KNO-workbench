# 신어 판별 — 고유명·혐오 표현 이진 체크 추가 설계

작성일: 2026-07-31 · 대상: `KNO-workbench` (prod)

## 목적

판별 카드(신어/비신어/판단 보류) 아래에 이진 체크 카드를 추가한다.
- **고유명 여부**: Y / N
- **혐오 표현 여부**: Y / N

두 체크가 모두 선택되지 않으면 **저장 자체가 불가**해야 한다(서버 강제). 나중에 Y 항목만 모아 별도 판단하는 것이 목적이므로, 저장된 모든 행은 두 값이 반드시 Y 또는 N임을 보장한다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 적용 단계 | 1차(작업자)·2차(검수자) 모두, 각각 독립 기록 |
| 필수 조건 | 판별값과 무관하게 항상 필수 (비신어여도 체크해야 저장) |
| 일치도 모드 | 동일 적용 (단일 1차 패널에 카드 추가) |
| 기존 프로젝트 | 적용 — 컬럼 없으면 서버가 자동 추가 |
| 컬럼명 | `1차 고유명 여부`, `1차 혐오 표현 여부`, `2차 고유명 여부`, `2차 혐오 표현 여부` |
| 저장값 | `Y` / `N` (빈 값 = 미판단) |
| 기존 판별 완료분(약 212건) | 판별 데이터 유지. 작업자가 항목을 다시 열어 체크만 선택 후 재저장 |

## 1. 데이터 스키마 (Code.gs)

- `HEADERS`: `1차 메모` 뒤에 `1차 고유명 여부`, `1차 혐오 표현 여부` / `2차 메모` 뒤에 `2차 고유명 여부`, `2차 혐오 표현 여부` 삽입 → 새 프로젝트 시트에 반영.
- **기존 시트 자동 마이그레이션**: 저장 시 해당 컬럼이 없으면 시트 끝에 헤더를 추가하고 인덱스를 재계산. 모든 접근이 `headerIndex_` 헤더명 기준이므로 컬럼 위치는 무관.
- `createProject`의 CLEAR 목록과 `genAgree`/`genReal`의 초기화 대상에 4컬럼 추가(재배분 시 빈 값으로 리셋).

## 2. 백엔드 저장 검증 (Code.gs)

- `saveFirst` / `saveSecond` payload 확장: `{ row_id, verdict, memo, proper, hate, op_id }`
- 검증: `verdict ∈ VERDICTS` 그대로 + **`proper ∈ {Y,N}` && `hate ∈ {Y,N}` 아니면 throw** `'고유명·혐오 표현 여부를 모두 선택해야 저장됩니다.'`
- 통과 시 판별·메모·체크값·일시·상태를 함께 기록(기존 락·멱등키 구조 유지).
- **일시 보존 규칙**: 재저장 시 판별값이 기존과 동일하면 `1차/2차 일시` 유지, 다르면 갱신. (기존 완료분에 체크만 추가하는 재저장에서 원래 판별 시각 보존)
- 변경로그: 기존 포맷 유지, 메모 컬럼 뒤 판별 컬럼에 `신어 (고유명N/혐오N)` 형태로 체크값 병기.

## 3. 프론트 UI (index.html)

- `stagePanel` 내 `verdictCards` 아래 **체크 카드 1개** 추가:
  - `고유명 여부  [Y] [N]`
  - `혐오 표현 여부  [Y] [N]`
  - 각 줄은 배타 토글(하나만 선택). 읽기 전용 패널에서는 값 표시만.
- 상태 관리: `SEL`과 별도로 `CHK = {'1차':{proper:'',hate:''}, '2차':{...}}`, `renderDetail` 시 항목 값으로 초기화.
- **저장 게이트** (`doSave`): 판별 + 두 체크 모두 선택돼야 저장.
  - 미완료 + 자동저장 → 발동하지 않고 배지에 `고유명·혐오 여부 선택 필요` (빨간색)
  - 미완료 + Ctrl+S/저장 버튼 → 빠진 항목을 토스트로 안내
  - 미완료 상태로 다른 항목 이동 → 저장하지 않고 경고 토스트 (입력값은 버려짐)
- 낙관적 반영·무손실 큐·`verifyJob_`는 기존 구조 유지, payload에 `proper`/`hate`만 추가.

## 4. 미체크 항목 추적 (기존 완료분 재작업용)

- `LIST_FIELDS`에 4컬럼 추가 → 목록에서 체크 여부 판별 가능.
- 목록 항목: 판별은 있으나 체크가 빈 항목에 `⚠ 체크 필요` 배지 표시.
- 상태 필터에 `체크 미완료` 옵션 추가(클라이언트 측 필터) → 작업자가 미체크 항목만 걸러 순서대로 처리.

## 5. 범위 외 / 보류

- dev(`KNO-workbench-dev`) 미러링: 별도 결정.
- 체크용 키보드 단축키: 미포함(요청 시 추가).
- 이미 저장된 빈 체크값의 일괄 백필: 없음 — 작업자 재저장으로 채움.

## 6. 배포

1. `Code.gs` 먼저 배포(구 프론트 + 신 백엔드 조합 시: 구 프론트는 proper/hate를 안 보내므로 저장이 거부됨 → **프론트·백엔드를 같은 시점에 배포**해야 함. Pages 반영 1~2분 시차는 허용).
2. 기존 배포 ID(`-i AKfycbxGQ25Q...`)로 재배포, `appsscript.json`의 webapp 블록 확인.
3. `index.html` 커밋 → push (Pages 자동 반영).
