- 다시 열 때 `origRebuild`가 등재표제어 조각으로 빈 행만 새로 만들고, 저장된 `원어` 문자열을 행으로 되돌리는 호출은 없음(`origFromField`는 원어 최종 칸을 직접 타이핑할 때만 실행). 성분 수정·행 이동(`data-touched`)도 화면 안에서만 유지.

## 복원 가능성 진단(저장된 조립 문자열 → 행)
"구간" = 원어 문자열에서 한자·한글·태그 붙은 외국어가 이어지는 단위. 어종 표시의 글자(한·고·영…)와 1:1이면 그대로 복원 가능.

| 구분 | 1차(302) | 2차(182) |
|---|---|---|
| 구간과 어종 글자 1:1 → 그대로 복원 | 167 | 92 |
| 같은 글자 종류가 붙어 경계 사라짐(`內亂犬`/`한+한`, `긁수저`/`고+고`, `go see look`/`영^영`) → 등재표제어 조각(음절 수)으로 분할 | 132 | 90 |
| 원어 구간이 어종보다 많음(1차 `逆Nixon外交`/`한^한` 등 3건, 2차에서 정정됨) | 3 | 0 |
- 성분 하나에 `+`로 행을 여러 개 만든 혼성어 유형(등재표제어와 다른 행 구조): 1차 39·2차 29 — 어종 표시의 `+` 위치와 원어의 태그·`←` 위치로 분할.
- 태그 없는 로마자(고유명 체크로 태그 생략): 1차 22·2차 7 — 고유명 체크로 복원.
- 기존 `origFromField`는 채워진 행과의 공통 접두·접미로 경계를 잡는 방식이라 빈 행에 쓰면 문자열 전체가 마지막 행에 몰림 → 로드 복원은 새 파서 필요.
- **결정(사용자)**: 등재표제어 조각 기준으로 나누고, 안 맞는 건은 목록으로 뽑아 사용자와 같이 본다.

## 착수 시 작업 순서(합의됨)
1. **백엔드** `WRITE_PART_FIELDS['형태부']`에 `원어 행` 추가 → `ensureCols_`가 저장 시 `1차 원어 행`·`2차 원어 행` 컬럼을 시트 끝에 자동 생성(기존 저장값 무영향, 헤더명 조회라 위치 무관). 점검(`validateWrite_`)은 손대지 않음. `clasp push --force` + `clasp deploy -i AKfycbxGQ25Q…` → @39. 배포는 작업자 없는 시간에.
2. **프론트** 원어 행을 숨은 `data-f="원어 행"` 칸에 JSON 배열(한 줄)로 직렬화: 행마다 `{성분, 원어, 언어, 고유명}`(순서 = DOM 순서, 손댄 상태 포함). 조립 문자열 `원어`·`어종 표시`는 그대로 함께 저장. 항목을 열 때 `원어 행` 값이 있으면 그 행을 그대로 복원(`origRebuild`보다 우선, `data-touched`=1로 두어 등재표제어 재생성 안 타게). 2차 폼도 동일, 1차 값 복사 시 행도 복사.
3. **기존 저장분 복원**(`원어 행` 비어 있을 때만): 등재표제어 조각 + 어종 표시 구조로 파싱해 행 생성. 어종 글자와 구간이 1:1이면 그대로, 붙어 있으면 조각 음절 수로 분할, 태그 없는 로마자는 고유명 체크. 안 맞는 건은 xlsx 목록으로 뽑아 사용자와 확인. (프론트 로드 시 폴백으로 넣을지, 시트에 일괄 기록할지는 착수 때 결정)
4. 검증: `orig_rows_check.py`·`lang_check.py`·`demo_check.py` 회귀 + 테스트 v3(`wt-mtghnu9u`) 실저장 왕복.
