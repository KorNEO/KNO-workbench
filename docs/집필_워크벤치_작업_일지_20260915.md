## 바뀐 동작
- **저장**: 원어 행(성분·원어·언어·고유명)을 JSON 배열 한 줄로 숨은 칸 `원어 행`에 직렬화(`origSerialize`, 화면 순서, 언어는 작업자가 고른 값만 — 자동값 한자어·고유어는 빈 값, 원어 글자가 하나도 없으면 빈 값). 저장 시 원어·어종 문자열과 함께 시트 `{n}차 원어 행`에 기록. 백엔드 `WRITE_PART_FIELDS['형태부']`에 `원어 행` 추가, 기존 시트엔 `ensureCols_`가 첫 저장 때 `1차 원어 행`·`2차 원어 행`을 끝에 생성. 점검(`validateWrite_`) 없음.
- **복원**: 항목을 열 때 `원어 행`이 있으면 그 행을 그대로 만든다(`origRestore`). 저장된 원어·어종 문자열은 덮어쓰지 않음. 복원 행은 손댄 행(`data-touched`)과 같이 취급 → 등재표제어를 바꿔도 재생성하지 않음. 깨진 JSON은 무시(조각 행).
- **2차**: 2차 `원어 행`이 없고 2차 원어도 없으면 1차 행을 물려받음. 2차 원어가 따로 저장돼 있으면 1차 행을 물려받지 않고 2차 원어 문자열에서 역파싱(`pv` 특례). "1차 작업 확정"은 `원어 행`도 복사(`PART_FIELDS`에 추가) 후 2차 행 상자를 초기화해 다시 만듦.
- **기존 저장분 역파싱**(`origParse`, 순수 함수): `원어 행`이 없고 처음 여는 항목(`data-json` 미설정)이면 원어·어종 표시·등재표제어에서 행을 만든다. 다시 조립한 결과(`origComposeCalc`)가 저장된 원어·어종과 완전히 같을 때만 적용. 규칙: 구간(한자/한글/`<태그>`외국어/태그 없는 로마자=고유명) → 어종 글자에 차례로 맞춤, 같은 종류가 붙은 구간은 등재표제어 조각 글자 수로 분할(內亂犬, 긁수저, `<중>谢谢政權`), 한 성분 안 여러 행은 글자·단어 하나씩, 기호(▼←)로 시작하는 로마자는 앞 로마자와 같은 언어, 기호만 있는 구간은 뒤 한자에 붙임.
- `origCompose`를 DOM 수집(`origRowUi`) + 순수 계산(`origComposeCalc`)으로 분리. 확인 창(`openWriteConfirm`)엔 `원어 행` 미표시. `chainApply`는 `원어 행` 칸을 건너뜀.
